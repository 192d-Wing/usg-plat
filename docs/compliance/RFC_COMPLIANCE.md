# RFC Compliance

Per-requirement status of the translator against the NAT64 / SIIT / NAT
behaviour RFCs. Paths are relative to `crates/`; test names are
`file::test` in the crate named. Tests ran on the macOS development host
(`make test` green after fix round 3; on branch `feat/cluster-ha`, `make test`
471 passed, 0 failed after its fix round 1). Deviations are stated in the row and
tracked in [`POAM.md`](POAM.md). Cluster (HA) rows describe the uncommitted
`feat/cluster-ha` working tree and are tested in-process only.

Decision order (both roles, every non-root certificate): OCSP (stapled,
cache, fetch), then CRL; `revoked` is final; attack-class failures (bad

when nothing is conclusive; `soft_fail` accepts only when no data at all
could be obtained (an accepted-risk setting: an on-path attacker who blocks
the plaintext responders makes the check pass, SEC-009); one shared
`budget_ms` per chain. Tests: `plat-tls/tests/chain.rs`,
`revocation_fallback.rs` (14 tests).

### Known deviations and limits (TLS and PKI)

- **RFC-007**: TLS 1.3 only, against RFC 5425 §4.2 (TLS 1.2 and
  `TLS_RSA_WITH_AES_128_CBC_SHA` mandatory). NDcPP also expects TLS 1.2.
- **RFC-105**: obs-fold header lines rejected instead of replaced by SP
  (RFC 9112 §5.2). Fails closed.
- **RFC-102**: directoryNames (IDP, CDP, issuer) are compared as DER bytes,
  not with the RFC 5280 §7.1 name-comparison rules; names that differ only
  in case or string type do not match. Fails closed.
- **RFC-103**: an IDP with more than 64 names (`MAX_IDP_NAMES`) makes the
  CRL unusable (`scope_mismatch`); only the first 16 names of a
  certificate's CDP (`MAX_CDP_NAMES`) are compared. Both fail closed.
- Delta and indirect CRLs, LDAP distribution points and the delegated OCSP
  responder's own status are not supported (POAM-025).
- v1 CRLs and OCSP non-successful responses are `malformed`; SHA-1
  signatures on OCSP responses and CRLs are `bad_signature` (fatal).
- `soft_fail` with plaintext HTTP responders is an accepted-risk setting
  (SEC-009); `hard_fail` is the default.

## Drop reasons relevant to conformance

`plat_drops_total{reason=...}` and `dataplane_counter` records name the
reason for each conformance-related drop:

- `source_route`: unexpired IPv4 LSRR/SSRR.
- `fragment`: non-first fragments, fragmented ICMP echo, fragmented ICMPv6
  errors, fragmented zero-checksum IPv4 UDP, and ICMP errors quoting a
  non-first fragment.
- `src_not_allowed`: non-client IPv6 sources, ICMPv6 errors from inside the
  NAT64 prefix, never-translatable IPv4 sources, and non-global IPv4 data
  sources under the default policy.
- `dst_forbidden`: never-translatable destinations, and non-global
  destinations under the WKP or under an NSP without the opt-in.
- `dst_not_translatable`: destinations outside the prefix or with a non-zero
  u-octet.
- `subscriber_table_full`: `nat64.max_subscribers` reached.
- `wrong_node`: traffic for a pool address this node does not own (another
  node's slice).
- `cluster_fenced` (HA): the slice is fenced or still adopting on this node.
- `missteered` (HA, `steering.mode = "drop"`): a new subscriber whose home
  is another member.
- `too_big`, `hop_limit`: see RFC 7915 §4.4/§5.4.

The `/metrics` counters `icmp_errors_generated`, `icmp_errors_rate_limited`,
`icmp_errors_translated` and `fragmented_v4_to_v6` count ICMP error
generation, rate limiting, translation and translator fragmentation.
