# RFC Compliance

Per-requirement status of the translator against the NAT64 / SIIT / NAT
behaviour RFCs. Paths are relative to `crates/`; test names are
`file::test` in the crate named. Tests ran on the macOS development host
(`make test` green after fix round 3). Deviations are stated in the row and
tracked in [`POAM.md`](POAM.md).

## Address mapping (RFC 6052, RFC 6890, RFC 8215)

| RFC | Requirement | Status | Location / test |
|-----|-------------|--------|-----------------|
| 6052 §2.2 | Prefix lengths 32/40/48/56/64/96; bits 64–71 (u-octet) zero | Implemented. Config rejects other lengths and a non-zero u-octet in the prefix. A destination inside the prefix with a non-zero u-octet is not extracted and is dropped as `dst_not_translatable` (`Prefix6052::extract`). | `plat-xlat/src/rfc6052.rs::rfc6052_table1`, `roundtrip_all_lengths`, `rejects_bad_prefixes`; `plat-common/src/config.rs::rejects_bad_prefix_len` |
| 6052 §3.1 | The Well-Known Prefix (WKP) 64:ff9b::/96 must not represent non-global IPv4 | Implemented (conformant by default). Under the WKP both destinations and IPv4 sources are refused for the full RFC 6890 Global=False table: 0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.0.0/24 except 192.0.0.9 and 192.0.0.10, 192.0.2/24, 192.168/16, 198.18/15, 198.51.100/24, 203.0.113/24, 224/4, 240/4. Config rejects the WKP combined with a pool that holds any non-global address. **Optional deviation**: `translation.wkp_non_global_icmp_errors` (default `false`) translates ICMPv4 errors from non-global router addresses under the WKP so traceroute and PMTUD hops stay visible; enabling it is a risk acceptance (POAM-022). | `rfc6052.rs` `is_non_global_v4`; `plat-nat64/src/engine.rs` `dst_forbidden`, `inbound_v4`; `rfc6052.rs::non_global_table`; `plat-nat64/tests/engine.rs::wkp_refuses_every_non_global_destination`; `plat-nat64/tests/hardening.rs::wkp_non_global_icmp_error_source_needs_switch`; `plat-common/tests/config_edges.rs::translation_edges` |
| 6890 (policy, SC-7) | Non-global IPv4 under a network-specific prefix (NSP) | Implemented, deny by default. `translation.allow_non_global_destinations` (default `false`) denies RFC 6890 non-global IPv4 destinations under every prefix, for data and for ICMPv6-error relay, and refuses non-global IPv4 **sources** of inbound data packets; ICMPv4 errors from non-global routers are still accepted under an NSP (PMTUD). The cluster's own `nat64.pool` is exempt from the non-global test in both directions, so a non-global pool still hairpins. Separately, a wire IPv4 packet whose source is inside this node's own pool slice is refused as `src_not_allowed` (SEC-301), including ICMPv4 errors (acceptable: this node never sends a packet sourced from its own slice onto the wire, RFC-302); sources in other nodes' slices are accepted, and the cluster edge must filter the pool prefix as an ingress source (POAM-024). Never-translatable space is always denied; the WKP ignores the opt-in. Release note: an NSP deployment that must reach RFC 1918, 100.64/10 or documentation space sets `allow_non_global_destinations = true`. The shipped example uses `64:ff9b:1::/96` (RFC 8215 local-use space, not subject to §3.1). | `engine.rs` `dst_forbidden`, `non_global_foreign`, `inbound_v4`; `hardening.rs::non_global_destinations_are_denied_by_default`, `non_global_sources_are_refused_under_default_policy`; `hardening.rs::wire_source_in_own_pool_slice_is_refused`; `config_edges.rs::non_global_destination_switch` |

## Header and ICMP translation (RFC 7915, RFC 6791, RFC 4443)

| RFC | Requirement | Status | Location / test |
|-----|-------------|--------|-----------------|
| 7915 §4 | Translator fragmentation of DF=0 IPv4 packets | Implemented. A DF=0 packet whose IPv6 translation exceeds `translation.lowest_ipv6_mtu` (default 1280, range 1280..=`ipv6_mtu`) is split into IPv6 fragments; Fragment Header Identification = IPv4 Identification; the transport checksum is computed over the whole datagram; an IPv4 first fragment keeps M=1. The worker transmits every fragment in order. Warning: a value above the real IPv6 path MTU black-holes large DF=0 traffic. | `plat-xlat/src/siit.rs` `v4_to_v6_fragments`; `engine.rs` `inbound_v4`; `hardening.rs::df0_packets_are_fragmented_to_1280`, `lowest_ipv6_mtu_raises_the_fragmentation_threshold`; `services/platd/src/run.rs::worker_transmits_every_fragment` |
| 7915 §4.1, §5.1 | Header translation | Implemented, with the deviation below. DF rule (IPv6→IPv4 result ≤ 1260 bytes → DF=0); IPv4 options dropped; flow label 0. Unexpired LSRR/SSRR is discarded (`source_route`); ICMPv4 3/5 is not sent (POAM-002). Hop-by-Hop accepted only as the first extension header (RFC 8200 §4.1). `translation.copy_tos` (default `true`) copies TOS/Traffic Class; `false` zeroes it on data packets and on the outer and quoted headers of translated ICMP errors; locally generated errors always use 0. | 7915 §4.4, §5.4 | Generate ICMP errors | Partial. ## Drop reasons relevant to conformance

`plat_drops_total{reason=...}` and `dataplane_counter` records name the
reason for each conformance-related drop:

- `source_route`: unexpired IPv4 LSRR/SSRR.
- `fragment`: non-first fragments, fragmented ICMP echo, fragmented ICMPv6
  errors, fragmented zero-checksum IPv4 UDP, and ICMP errors quoting a
  non-first fragment.
- `src_not_allowed`: non-client IPv6 sources, ICMPv6 errors from inside the
  NAT64 prefix, never-translatable IPv4 sources, and non-global IPv4 data
  sources under the default policy.
- `dst_forbidden`: never-translatable destinations, and non-global
  destinations under the WKP or under an NSP without the opt-in.
- `dst_not_translatable`: destinations outside the prefix or with a non-zero
  u-octet.
- `subscriber_table_full`: `nat64.max_subscribers` reached.
- `too_big`, `hop_limit`: see RFC 7915 §4.4/§5.4.

The `/metrics` counters `icmp_errors_generated`, `icmp_errors_rate_limited`,
`icmp_errors_translated` and `fragmented_v4_to_v6` count ICMP error
generation, rate limiting, translation and translator fragmentation.
