# RFC Compliance

Per-requirement status of the translator against the NAT64 / SIIT / NAT
behaviour RFCs. Paths are relative to `crates/`; test names are
`file::test` in the crate named. Tests ran on the macOS development host
(`make test` green after fix round 3; on branch `feat/cluster-ha`, `make test`
471 passed, 0 failed after its fix round 1; on branch
`feat/protocol-completeness`, `make test` 557 passed, 0 failed, 0 ignored
after its fix round 2, macOS, 2026-10-29).
Deviations are stated in the row and tracked in [`POAM.md`](POAM.md) or in
"Protocol deviations" below. Cluster (HA) rows describe the uncommitted
`feat/cluster-ha` working tree and are tested in-process only. Fragment and
ICMP-generation rows describe the uncommitted `feat/protocol-completeness`
working tree (stacked on `feat/cluster-ha`).

## Protocol deviations (feat/protocol-completeness)

Each is a deliberate choice, implemented as stated and covered by the cited
tests in the rows above.

1. **ICMPv6 error source** (RFC 4443 §2.2, RFC-001): without
   `translation.icmp_source_v6` the source of a locally generated ICMPv6
   error is the synthesized destination of the offending packet, which can
   make IPv6 traceroute show the IPv4 destination at the PLAT hop.
2. **Filter-gated errors** (NIST-002/004, SEC-005): Fragmentation Needed,
   inbound Time Exceeded and Source Route Failed are sent only when the
   read-only inbound filter would admit the packet. Otherwise the packet is
   dropped silently as `no_binding` / `filtered` (Source Route Failed keeps
   `source_route`), so they are no binding-activity oracle. Inbound TTL ≤ 1
   packets that were counted `hop_limit` before are now counted `no_binding`
   / `filtered` when refused.
3. **Source Route Failed off by default** (`send_source_route_failed =
   false`): source-routed IPv4 is dropped silently unless enabled.
4. **Inbound Destination Unreachable off by default** (user decision Q1,
   RFC 6146 §3.5.2.2/§3.5.4 SHOULD): `send_inbound_unreachable = false`,
   so pool scans get no answer; TCP is always silent.
5. **ICMP rate limits**: a quarter of the per-worker bucket is reserved for
   PMTU errors (Packet Too Big, Fragmentation Needed), so other local errors
   get at most 3/4 of `icmp_errors_per_sec`, which must be 0 or ≥ 4.
   Translated (router-originated) errors are not rate-limited; each needs a
   validated live mapping.
6. **Fragment authorisation and caps**: early non-first fragments of
   ICMPv6 errors from non-client routers are not held (they need the first
   fragment to arrive first); per-source caps are fixed fractions of the
   configured limits; inbound reassembly requires the filter to admit the
   datagram.
7. **No Unreachable for `port_exhausted` in a sliced pool** (RFC-003,
   NIST-005): in a cluster slice pool `port_exhausted` gets no ICMPv6
   Destination Unreachable, because during failover it is also what a node
   without an active or reserve-backed slice reports, which is transient;
   other limit reasons still answer, and legacy pools answer 1/3.
8. **IPv4 Identification uniqueness** (RFC 6864): unique per counter for at
   least 8192 packets (65536 / maximum step 8), not tracked per flow.
9. **Parameter Problem scope** (RFC-005): generated only for an active
   Routing header; other unsupported extension headers (Hop-by-Hop not
   first, duplicate Fragment Header) are silent drops.
10. **Extension headers after the Fragment Header** (RFC-006): refused as
   `unsupported_proto`, because they would shift every later fragment's
   offset in the IPv4 result.
11. **Cross-node hairpin off by default** (RFC 4787 REQ-9, RFC 6146 §3.8
   MUST; RFC-001 of the POAM-020/024/013 review, user decision): with
   `translation.cross_node_hairpin = false` (default) every wire IPv4
   packet sourced inside `nat64.pool` is refused as `src_not_allowed`
   (POAM-024), which includes a hairpin between two cluster nodes.
   Single-node deployments and same-node hairpins conform (they are looped
   back in-process). A cluster that must hairpin across nodes sets
   `cross_node_hairpin = true` and `translation.cluster_interfaces`; platd
   then refuses to start unless the host forward policy drops pool sources
   arriving outside those interfaces (`hairpin_guard.rs`).
12. **Pool-source filtering is intentional (BCP 38 / RFC 2827, RFC-002/003)**:
   a pool-sourced IPv4 packet from the wire is spoofed unless it is a
   guarded cross-node hairpin, so it is dropped silently (`src_not_allowed`,
   no ICMP error is generated, so the refusal is no oracle and cannot be
   reflected).

Also: an IPv4 fragment is never answered with Fragmentation Needed (its DF
bit is ignored and it is re-split); an IPv6 fragment whose IPv4 translation
exceeds `ipv4_mtu` is split as IPv4 fragments (DF=0) rather than answered
with Packet Too Big; a hairpinned ≤ 1280-byte packet above `ipv4_mtu` is
looped back whole.

Decision order (both roles, every non-root certificate): OCSP (stapled,
cache, fetch), then CRL; `revoked` is final; attack-class failures (bad
signature, unauthorized responder, nonce or CertID mismatch, wrong CRL
issuer) reject in every mode with no fallback; `hard_fail` (default) rejects
when nothing is conclusive; `soft_fail` accepts only when no data at all
could be obtained (an accepted-risk setting: an on-path attacker who blocks
the plaintext responders makes the check pass, SEC-009); one shared
`budget_ms` per chain. Tests: `plat-tls/tests/chain.rs`,
`revocation_fallback.rs` (14 tests).

### Known deviations and limits (TLS and PKI)

- **RFC-007**: TLS 1.3 only, against RFC 5425 §4.2 (TLS 1.2 and
  `TLS_RSA_WITH_AES_128_CBC_SHA` mandatory). NDcPP also expects TLS 1.2.
- **RFC-105**: obs-fold header lines rejected instead of replaced by SP
  (RFC 9112 §5.2). Fails closed.
- **RFC-102**: directoryNames (IDP, CDP, issuer) are compared as DER bytes,
  not with the RFC 5280 §7.1 name-comparison rules; names that differ only
  in case or string type do not match. Fails closed.
- **RFC-103**: an IDP with more than 64 names (`MAX_IDP_NAMES`) makes the
  CRL unusable (`scope_mismatch`); only the first 16 names of a
  certificate's CDP (`MAX_CDP_NAMES`) are compared. Both fail closed.
- Delta and indirect CRLs, LDAP distribution points and the delegated OCSP
  responder's own status are not supported (POAM-025).
- v1 CRLs and OCSP non-successful responses are `malformed`; SHA-1
  signatures on OCSP responses and CRLs are `bad_signature` (fatal).
- `soft_fail` with plaintext HTTP responders is an accepted-risk setting
  (SEC-009); `hard_fail` is the default.

## Drop reasons relevant to conformance

`plat_drops_total{reason=...}` and `dataplane_counter` records name the
reason for each conformance-related drop:

- `source_route`: unexpired IPv4 LSRR/SSRR.
- `fragment`: reassembly disabled (`reassembly_slots = 0`) for a class
  that needs it, fragmented zero-checksum IPv4 UDP under
  `udp_zero_checksum = "drop"`, and other fragment shapes the translator
  cannot handle (for example an ICMPv6 error reaching the unfragmented error
  path with a Fragment Header).
- `fragment_timeout`, `fragment_overlap`, `fragment_tiny`,
  `fragment_too_many`, `fragment_table_full`, `fragment_buffer_full`,
  `reassembly_full`, `reassembly_too_big`, `fragment_unmatched`,
  `icmp_quote_unmatched`: see "Fragments" above.
- `src_not_allowed`: non-client IPv6 sources, ICMPv6 errors from inside the
  NAT64 prefix, never-translatable IPv4 sources, and non-global IPv4 data
  sources under the default policy.
- `dst_forbidden`: never-translatable destinations, and non-global
  destinations under the WKP or under an NSP without the opt-in.
- `dst_not_translatable`: destinations outside the prefix or with a non-zero
  u-octet.
- `subscriber_table_full`: `nat64.max_subscribers` reached.
- `aggregate_subscriber_limit`: the new subscriber's `nat64.aggregate_prefix_len` prefix already holds `nat64.max_subscribers_per_aggregate` subscribers.
- `wrong_node`: traffic for a pool address this node does not own (another
  node's slice).
- `cluster_fenced` (HA): the slice is fenced or still adopting on this node.
- `missteered` (HA, `steering.mode = "drop"`): a new subscriber whose home
  is another member.
- `too_big`, `hop_limit`: see RFC 7915 §4.4/§5.4. A counted drop may also
  have been answered with an ICMP error.

The `/metrics` counters `icmp_errors_generated`, `icmp_errors_rate_limited`,
`icmp_errors_translated`, `icmp_time_exceeded_sent`, `icmp_unreachable_sent`
(includes Source Route Failed), `icmp_param_problem_sent`,
`fragmented_v4_to_v6`, `fragmented_v6_to_v4`, `fragments_in_v6`,
`fragments_in_v4`, `fragments_forwarded`, `fragments_buffered` and
`datagrams_reassembled`, and the gauge `plat_fragment_entries`, count ICMP
error generation, rate limiting, translation, translator fragmentation and
fragment handling.
