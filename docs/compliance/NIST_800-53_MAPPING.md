Version 0.1.0 plus branch `feat/fips-tls` (unreleased), branch `fix/linux-validation`
(unreleased), SIEM log schema 6 (`plat_audit::LOG_SCHEMA_VERSION`). Linux
evidence: [`LINUX_VERIFICATION.md`](LINUX_VERIFICATION.md) (Lima VM, Ubuntu 24.04.5 aarch64, kernel 6.8,
systemd 255, chrony; 2026-10-29).

Status values:

- **Implemented**: code plus automated test evidence. Tests ran on the macOS
  development host (`make test` on `feat/fips-tls` after its fix round 1: 38
  suites, 0 failed, 0 ignored; unchanged after fix round 2). TLS-enabled code was not compiled for
  aarch64-linux on that host (no cross C compiler); CI does that.
- **Implemented (verified on Linux)**: the mechanism is in `deploy/` or in
  Linux-only code (`#[cfg(target_os = "linux")]`, the TUN backend), with no
  or only partial automated test, and the cited items of
  [`LINUX_VERIFICATION.md`](LINUX_VERIFICATION.md) passed on one Linux host
  (a single-host lab, not a production deployment). Items marked PARTIAL or
  pending there are named in the row.
- **Implemented (not tested on Linux)**: as above, but the Linux item has not
  passed yet.
- **Partial**: some of the control is implemented and tested; the gap is
  named with its POA&M ID.
- **Planned**: not implemented; tracked in [`POAM.md`](POAM.md).
- **Inherited**: provided by the platform or the site.

Paths are relative to `crates/` unless they start with `services/`,
`deploy/` or `config/`. Test names are `file::test` in the crate named.
